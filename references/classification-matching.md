# 专业分类匹配

用于将用户的自然语言研究方向映射到目标期刊当前可选的 Personal Classifications 或稿件分类。由助手进行语义判断，浏览器负责读取候选、选择与核验；不依赖固定词库或字符串相似度打分。

## 输入与候选

- 作者 YAML 沿用最小字段模板；目标期刊新增的必填字段按当前表单补充，不固定为六项。`classifications` 仍为字符串数组，允许每项是正式分类、模糊描述、简称或中英文研究方向。空数组表示信息缺失，不按期刊名替用户推断专长。
- 先区分个人专长与稿件主题，结合用户本次提供的相关上下文理解研究对象、方法和应用领域。拆分真正独立的方向，保留复合描述中的限定条件、否定和排除项；方法或工具的提及本身不证明作者在该领域具有专长。
- 为原描述生成少量语义等价的英文表达、同义词及明确的缩写展开，依次在分类窗口检索。简称有多义时用上下文消歧，不凭最常见含义直接选择。
- 从当前页面取得候选的完整名称、可见代码、上级路径及说明（如有），展开相关分支并比较相邻项。无搜索功能时浏览相关分类树；一次搜索无结果时换等价表达或检查上级分支。相关路径仍无法读取时记录范围限制，不声称全表无匹配。
- 候选必须来自当次页面可选列表；历史记录仅作检索线索。相同名称出现在不同分支时按完整路径区分。不构造分类代码，也不将自由文本直接当作固定选项提交。

## 决策与自动选择

逐个原始方向比较候选的含义、对象、应用范围及层级，不把关键词重合或抽象的“最相似”当作选择依据。

| 匹配关系 | 决策 |
|---|---|
| 原描述与正式分类同义，或上下文足以明确对应且无同样合理的冲突候选 | 在已授权填写范围内自动选择，不再逐项询问 |
| 只有上级分类准确覆盖原描述；更细分类不存在、不可选，或需要用户未提供的限定条件 | 可自动选择准确且可选的上级，注明粒度较宽；用户要求精确子类时再澄清 |
| 两个及以上互斥或不同含义的候选同样合理；简称多义且上下文不能排除 | 展示最多三个有实际差异的候选及路径，用一个简短问题确认；不同时全选来掩盖歧义 |
| 仅相邻领域、工具相同或词形接近，含义不符 | 不选；继续查同义表达及相关分支，仍无可靠匹配则记录未匹配并询问必要的研究背景 |

优先选择证据支持的最具体且可选分类。不能为了选择叶节点而补造研究对象、应用场景或资格，也不能为了满足最少数量而选择无关类别。无需给语义判断编造概率或固定置信度分数。

多个明确方向可分别匹配，按当前页面最少/最多数量约束去重。同一具体含义不主动重复选父子分类；系统自动加入的上级需保留并注明。多个方向指向同一分类只加一次。超过上限时按用户已说明的重点或当前稿件的核心主题取舍；重点不明且会改变结果时再询问。已有正确选择应复用，未获修改意图时不删除其他已保存分类。

## 执行与保存

1. 原始输入与候选对照先记录在任务目录，内容为：原描述、所用上下文、候选正式名称/代码/路径、选择或排除理由、是否待确认。记录与真实资料均不进入通用技能包。
2. 已授权填写时直接添加明确匹配项；有歧义的项暂缓，只询问该项。缺项仅阻塞依赖它的步骤。用户只要求资料准备时交付候选映射，不操作账号。
3. 按当前界面确认勾选、添加、已选列表及保存结果。APEN 分类窗口需 Submit；具体操作见[注册表实测](applied-energy-registration.md)。页面变化后重新定位，不复用旧控件编号。
4. 保存后回读正式名称、可见代码及自动带入的上级分类，按同一含义核对是否遗漏或误选。未保存或保存状态不明时不报告完成。
5. 全部输入方向已解决且网页保存核实后，可将任务 YAML 的 `classifications` 更新为实际保存的正式条目；若仍有未解决描述，保留原数组并在任务记录中分别列出已保存与待确认项。准备阶段或保存失败时不提前覆盖原描述。再次执行先读取用户最新 YAML，再核对已有选择，避免重复添加。

向用户简要说明“原描述 → 实际分类”及选择理由；将较宽的上级匹配、自动带入父级、未匹配项和真实保存状态说明白。不要把推断的分类说成用户逐字提供，也不要在通用模板中增加个人研究方向或具体分类示例。
